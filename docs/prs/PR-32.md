# PR #32 — Puntos por fase: 0 → 10

- **Rama:** `fix/phase-points-value` → `dev`
- **Fecha:** 12 nov 2026, mergeado 06:19 UTC
- **Autor:** Brandon (con Claude)

## Por qué

`POINTS_PER_PHASE` en `apps/web/src/features/event/server/board.ts` estaba en **0** desde que Eddy
lo dejó así el 8 nov como default ("mientras el equipo decide", tabla de decisiones de
`docs/backend/ESTADO-BACKEND.md`). Nadie confirmó un valor final — un equipo podía completar las 8
fases del evento y terminar con 0 puntos, sin que la UI avisara que algo estaba mal. Encontrado por
Brandon al revisar el código de la sección de puntajes, no reportado por nadie más.

## Qué cambió

```diff
- export const POINTS_PER_PHASE = 0;  // 0 until the team decides the scoring...
+ export const POINTS_PER_PHASE = 10; // Points a team earns per completed phase.
```

Un solo valor, usado por `prisma.team.update({ data: { score: { increment: POINTS_PER_PHASE } } })`
en `app/api/board/keys/[key]/phases/[order]/route.ts`.

## Pruebas

- Verificado en vivo: se completó una fase a través de la UI real y `GET /api/board` respondió
  `{"score":10}`.
- Suite unitaria y e2e completas en verde.
- Confirmado después en producción (ver `docs/testing/QA-2026-11-12.md` sección 4): el valor en
  `main` es 10, no 0.
